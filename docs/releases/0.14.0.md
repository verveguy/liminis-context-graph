# 0.14.0 — 2026-09-02 (full release notes)

The graph engine moves onto lbug 0.20.1, and the entity-name lookup that ADR-0038 kept in process
memory is now served by a database-native index. Around that, the embedder became something you can
point at a hosted provider, WAL replay stopped carrying 90% dead weight, and episodes gained
structured metadata. **This release carries a one-way database migration and one breaking API
change — read Upgrading first.**

### Upgrading

1. **The database migrates one way.** A 0.13.x database (storage version 41) opens directly — no
   export, no reimport, WAL untouched. The first checkpoint rewrites it to storage version 47,
   after which **an older binary will not open it again**. To roll back: stop the service, move
   `.lcg/db/` aside, start the old binary; it rebuilds from the WAL.
2. **First start does real work on a large graph.** The new `Entity.lookup_key` ART index is built
   by a one-shot backfill that scans every entity and **blocks** while it runs. Budget for it
   proportional to entity count.
3. **Run `knowledge_backfill_summary_embeddings` after upgrading.** Existing entities get a zero
   vector for the new `summary_embedding` column, so summary semantic search returns nothing useful
   until the backfill runs. It is an explicit admin call, not automatic.
4. **BREAKING — `facts` is now `edges`.** `knowledge_find_relationships` and
   `knowledge_list_relationships` changed their response key. A client still reading `facts` gets a
   **silently empty list**, not an error. Update integrators before upgrading.

### Added

- **Episodes carry structured metadata.** `knowledge_process_chunk` and `knowledge_add_episode`
  both accept an optional `attributes` map, stored on a new `Episodic.attributes` column and
  returned by `knowledge_get_episodes` and `knowledge_search_passages`. Since `MENTIONS` already
  runs Episodic → Entity, a document's metadata and the facts extracted from its prose are now
  reachable in one traversal. Survives a WAL dump → replay round trip. Reported from the orac
  project (#525). See ADR-0528. (#528)
- **The embedder accepts an API key**, so hosted providers work, not just unauthenticated local
  servers. Resolved from `LCG_EMBEDDING_API_KEY`, then `GRAPHITI_EMBEDDING_API_KEY`, then
  `OPENAI_API_KEY`; sent as a Bearer token on the HTTP transport only. Kept out of logs, telemetry
  and recorded cassettes; URL userinfo is redacted before any URL is logged. (#497, #509)
- **Entity summaries are semantically searchable** via a new `Entity.summary_embedding` column and
  vector index. Existing entities are zero-filled at migration — see Upgrading step 3. (#470)
- **`knowledge_status` reports per-group ontology drift** via `group_ontology_drift`. A group not
  yet used is absent rather than reported as "not drifted", so the field is never a false
  all-clear. (forward-ported from 0.13.4, #451)
- **MCP client configuration recipes** for pointing the embedder at Ollama, LM Studio, a hosted
  provider, or an explicit UDS path — including the resolution order and the fact that a running
  sidecar silently wins over `LCG_EMBEDDING_URL`. (#498)
- **The docs site publishes from release tags** rather than `main`, keeping every released version
  available. (#477)

### Changed

- **The in-process entity-name lookup map is replaced by a database-native ART index.** ADR-0038's
  `NameIndex` — which the host had to invalidate on every mutation path — gives way to a
  materialized `Entity.lookup_key` column and a secondary ART index over it. Removes the
  invalidation surface, the full-`Entity` startup scan, and a duplicated copy of database state.
  Resolution semantics are unchanged, including resolving through `Merged` tombstones (ADR-0283).
  `knowledge_status` keeps `name_index_trusted` and `name_index_fallback_scans` with remapped
  meanings. See ADR-0221 and Upgrading step 2. (#221)
- **Embedding vectors are no longer written to the WAL.** They were **89.9% of WAL bytes** on the
  reference corpus (66.9 MB of 74.4 MB), since each `f32` becomes a JSON decimal literal. Replay
  now always recomputes from co-located source text through a content-addressed cache, and a vector
  found in an older WAL is ignored. (#526, #440)
- **Embedding calls are batched** across ingest and the WAL-replay recompute path, rather than one
  round trip per text. (#445, #486)
- **BREAKING: the relationship list is returned under `edges`, not `facts`**, on
  `knowledge_find_relationships` and `knowledge_list_relationships`
  (`knowledge_get_edges_by_group` already used `edges`). See Upgrading step 4 and ADR-0020. (#524)
- **lbug 0.17.0 → 0.20.1**, moving the crate pin and the native-bundle pin (`LBUG_VERSION`)
  together in a single hop. Picks up upstream's hung-process and checkpoint lock-file fixes, WAL
  group commits, stats-aware planning, plus fixes on paths this project exercises: FTS heap
  corruption when scans race committing writers (`ladybug#845`), primary-key-lookup row alignment
  (`ladybug#837`), and silent row loss on `MATCH` primary-key predicates (`ladybug#864`). No IPC or
  MCP schema, response shape, or dispatch changes. See Upgrading step 1.
  (#398, #529 — superseding #190 and #220.)

### Fixed

- **A hung embedder can no longer stall the service indefinitely.** `OaiEmbedder`'s HTTP client had
  no request or connect timeout, so an endpoint that accepted a connection and never responded hung
  the caller — holding the instance-wide write lock. Both are now bounded and configurable via
  `LCG_EMBEDDING_TIMEOUT_MS` (30s) and `LCG_EMBEDDING_CONNECT_TIMEOUT_MS` (5s). The UDS transport
  has the same hazard, tracked in #541. (#510)
- **An unreachable embedder no longer kills a `--mcp-stdio` launch.** The startup probe retries with
  bounded backoff (5s), and if exhausted in standalone `--mcp-stdio` mode the service starts
  degraded and reports why through `knowledge_status` rather than exiting with a diagnostic a GUI
  client discards. Hand-started socket mode keeps fail-fast. Auth failures (401/403) are always
  fatal. (#499)
- **Assert handlers no longer embed before checking existence**, so an update that discards the
  vector no longer pays for it. (#444)
- **Legacy WAL migration files its stream under the right group.** (#467)
- **Streaming WAL rebuild reports its own backfill outcome** as `lookup_key_backfill_ok`, distinct
  from `indices_built`. (#491)
- **A concurrent remediation's ontology-drift clear is no longer overwritten** by a stale
  first-resolution insert. (#495)
- **Cross-group episode deletes are attributed to the right WAL stream**, via one scoped query per
  group inside an explicit transaction. (#402)
- **Release binaries carry no dynamic OpenSSL dependency.** OpenSSL is linked statically, so the
  single-binary install stays self-contained. Building from source needs OpenSSL 3 development
  files; installing a released binary needs nothing. See ADR-0398.
- Forward-ported from the 0.13 maintenance line: the edge `episode_uuids` documentation correction
  (#410) and per-group ontology drift detection (#451), both released in 0.13.4. Called out because
  the maintenance branch was cut from `v0.13.3` — a higher version number does **not** by itself
  imply it contains an earlier patch release's fixes. (#494)
